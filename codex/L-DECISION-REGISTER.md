# L — Decision Register

Дата: 2026-10-09. База `c7a500f`, L0 documentation only. **FACT** — проверено кодом/документом или явно принято владельцем; **PROPOSAL** — рекомендация; **DECISION REQUIRED** — ответ владельца; **UNKNOWN** — нет исходных данных. PROPOSAL не означает accepted. В L0 закрыты только D1–D3, уже принятые в задании. Все owner gates открыты.

Переход в ACCEPTED требует записи decision/date/owner/evidence и обновления затронутых ADR/плана. Технические B решения инженер может принять в разрешённом этапе после указанной проверки; L0 не разрешает implementation. Отсутствие ответа не является согласованием. [Архитектура](L-ARCHITECTURE.md), [этапы](L-IMPLEMENTATION-PLAN.md), [краткие вопросы](L0-RESULTS.md).

## Минимум для следующего запуска

Для **L1 на синтетических данных** нужны ответы C01 и C02 и новое явное разрешение L1 после рассмотрения L0. Рекомендуемый пакет: manual CLI, одна роль, approved roster/scopes; одноразовые activation/reset codes через проверенного оператора, без обязательного email/SMTP. Cookie/mapping/session детали — B01–B03, их инженер обосновывает тестами. C08/C09 и точные люди/доступы обязательны перед созданием реальных accounts, даже если L1 технически завершён. C03–C09 нельзя считать закрытыми после принятия первых двух решений.
