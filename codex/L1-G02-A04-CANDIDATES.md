## C04-1: AWS S3 + RDS PostgreSQL + EC2/Envoy + Step Functions

Выбран доступный как коммерческий продукт стек с backend WORM, синхронной DB-репликацией и supervisor вне guest OS. Это позволяет проверить наиболее существенные пробелы A03 без разработки storage gateway. Компоненты используют один AWS region `us-east-1`; Multi-AZ означает **DB instance с одним standby**, не Aurora, не Multi-AZ DB cluster и не asynchronous read replica.

| Слой | Конкретный исследуемый профиль | Версия / применимость / предел |
|---|---|---|
| Storage | S3 Standard, general-purpose bucket; Versioning Enabled; Object Lock COMPLIANCE, фиксированная retention на каждой опубликованной версии; адресация `(bucket,key,versionId)`; SSE-S3; без CRR/lifecycle deletion | Managed service, backend build/firmware не раскрыты и не pin-able в этом исследовании. S1–S3/S5. Retention должна покрывать всё требуемое время хранения; срок не утверждается A04 |
| Доступ к storage | Private S3 gateway endpoint; bucket explicit deny вне endpoint и вне роли writer; Block Public Access; workers без прямых S3 credentials, без presigned upload/download URLs; отдельная management role | S4 описывает endpoint restriction. Полный IAM/credential/route audit отсутствует; политика — proposed configuration, не доказанный no-bypass invariant |
| Physical fencing attempt | Внешний `EC2 StopInstances(Force=true)` для writer/edge; IAM revoke/deny и S3 AbortMultipartUpload как дополнительные меры | F1–F3, S2. Это конкретный проверяемый **кандидат механизма**, а не установленный physical fence на S3 mutation point. Уже принятый S3 I/O независим от EC2 guest |
| PostgreSQL | Amazon RDS PostgreSQL **17.6**, Multi-AZ DB instance, gp3, private endpoint; `fsync=on`, `synchronous_commit=on`, `full_page_writes=on`; без read replicas для outcome resolution, без 2PC/prepared transactions | P1–P6. RDS service/storage build не раскрыт. Наличие 17.6 в release notes не подтверждает возможность создать именно эту версию в аккаунте/регионе сегодня; API availability/parameter inspection не выполнялись |
| Compute / edge | Две отдельные EC2 `m6i.large` для execution и edge, Ubuntu Server 24.04 LTS amd64 / GA Linux 6.8; Envoy **1.35.0**, HTTP/1.1 + HTTP/2, HTTP/3 выключен; прямой TLS ingress, без ALB/NLB/CDN | E1–E3. AMI ID, kernel patch/build, ENA/firmware/image digest не установлены; это препятствие полной version qualification, не право приписать managed fabric свойства Linux |
| Edge policy | `common_http_protocol_options.max_stream_duration` по классу запроса ≤60s/≤480s; request/header/idle timers дополнительные; retries и internal redirects выключены; штатный delayed close, не «исправление» через zero | E1/E2. Эти значения — потолки T04 для анализа настройки, не доказанные ingress-to-wire bounds и не утверждённые runtime настройки. Неизвестный termination tail не оставляет доказанного usable budget |
| Supervisor | AWS Step Functions **Standard**, версия ASL `1.0`: per-operation absolute `Wait.Timestamp`, затем AWS SDK integration `ec2:stopInstances` и наблюдение состояния; независимая IAM execution role | U1–U3, F1/F3. Дефиниция/immutable execution version не создана; service build не опубликован. Supervisor вне EC2 процесса/ядра; общие AWS region/control plane/IAM/сети остаются correlated dependencies |
| Время / scheduler | Amazon Time Sync NTP `169.254.169.123`, Ubuntu chrony 4.5; monotonic elapsed в guest, conservative UTC для admission; обычный Linux scheduler | C1. NTP/PTP/RX timestamp precision не подменяют bound всех часов и dispatch. RT scheduler/hardware watchdog не заявлены |

Профиль совместим на уровне интерфейсов HTTPS/S3, PostgreSQL и EC2 API. Не заявлена готовая интеграция с LMS: единственный writer boundary и передача trusted admission deadline в supervisor остаются обязанностями принятого дизайна, не реализованными компонентами. Отсутствие готового gateway дополнительно запрещает приписывать C04-1 invariants A02. Не смешиваются свойства S3 directory buckets, S3 Express/Outposts, Aurora и RDS single-standby.

Практическая доступность: продукты документированы, Envoy имеет точный release tag; ресурсы не приобретались, capacity/quota/region/AMI и право аккаунта на создание RDS17.6 не проверены. Поэтому «можно заказать компоненты» не означает «получен contract-qualified deployment». Полностью pinned kernel/NIC/storage/control-plane dossier отсутствует явно, а не восполняется вымышленными версиями.

## Источники и область применения

Проверены в рамках A04 2026-10-09. AWS `latest` — изменяемая публичная документация, не архивный договор с владельцем и не версия backend; PG `/17/` — документация major 17, не certification RDS build 17.6. Отрицательный вывод означает: **в перечисленных источниках требуемый worst-case contract не установлен**, а не что скрытого коммерческого соглашения не может существовать. Соглашение с дополнительными гарантиями не предоставлено. `CONTRACTUALLY ESTABLISHED` далее применяется только к узкой документированной семантике, не к отсутствующему end-to-end SLA.
