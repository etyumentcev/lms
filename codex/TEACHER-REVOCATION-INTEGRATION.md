## Contract and scope

Actor → authenticated scoped teacher. Use cases → review/revise/accept, message, upload, delete pending upload, private file read; scoped login/refresh/switch. Invariants → existing JWT validation and ScopePolicy, server-resolved immutable ownership, current conservative processing checks, original deadline, one durable attempt, no result after cutoff, no automatic replay after unknown COMMIT. Entities → Work, Submission, Review, Message, Attachment and immutable attempt. State machine → existing `ProblemWorkService`/domain `Submit → Review → Revise → Accept`; no new transition or role.

New host inputs are signed `AccessToken` plus server-captured `ApplicationDeadline`. Actor/org/grants are never DTO inputs. Resource IDs select server-resolved ownership. All new commands fail before effects without valid teacher JWT or live qualified deadline. `TeacherRevocationHttp` also refuses a missing ingress feature, requires the scoped bearer scheme on educational routes, HTTPS and exact allowed Origin plus ASP.NET antiforgery on unsafe requests. Install `CourseRequestIngress` before body/auth/routing and register the existing qualified clock, ComponentJwt, context factory, private storage and commands. Do not map legacy controllers in that isolated host. There is no background executor or queue/resume endpoint.

The existing 60-second ordinary ingress is retained for this isolated HTTP composition; it does not manufacture a fresh 30-minute deadline in a handler. Internal TeacherOperation ingress may use the existing 1800-second maximum. All budgets include the existing 30-second completion reserve.

## Transaction and replay details

Admission validates JWT, resource ownership and processing before reservation; after DB waits it validates JWT again. The immutable authority snapshot then belongs to that operation. Ordinary revoke does not perform per-stage grant refresh, and a refreshed credential cannot be substituted into the running operation.

Attempt reservation uses its own clean READ COMMITTED context and existing organization lock. The additive migration allows exactly one of natural expectedVersion or stable nonempty IntentId. It preserves all old rows, immutable triggers and versioned unique constraint, and adds an unversioned unique index. Fingerprint mismatch conflicts. New transport keys do not bypass either unique identity. Reservation ACK is not domain success. A process lost after reservation can leave an attempt with no effects; no automatic resume or deletion is supplied.

For domain/metadata mutation, the new executor owns READ COMMITTED transaction and existing `processing_lock(org)` (organization → processing guard). It re-resolves the immutable resource and checks current conservative processing in that transaction before mutation and before COMMIT. History authors and annotation files are included. Aggregate CAS and attachment claims remain in the existing store/domain protocol. `SaveInTransaction` is internal, requires an existing transaction and original deadline, and cannot commit independently. An EF execution strategy configured for automatic retries is rejected by the new writer.

The original deadline dispatches the one COMMIT and records Unknown until ACK. An exception after a committed mutation cannot start a second executor because the reservation already exists. Late ACK records an external committed fact but fails the result gate. For review/message the existing DomainEvents remain atomic with history. For upload/delete the attempt plus metadata/tombstone are evidence; there is **no new atomic committed-result/audit ledger or public status resolver**. A conflict must not be presented as confirmation that the original operation committed.

Files are deliberately outside DB transactions. Upload is private before eligibility; failure retains originals. Delete commits a tombstone before physical cleanup and returns no successful result after deadline. File/DB atomicity is not claimed. File keys for unknown orphan uploads currently require explicit reconciliation; there is no safe automatic “SELECT not found → delete” rule.

## Temporal proof and its limits

Let R be committed ordinary revocation and A the latest admission under a previously issued JWT. Existing issuer/revoke serialization plus JWT ≤15 minutes gives A < R+15m. The original cutoff D ≤ ingress+30m ≤ A+30m, hence D < R+45m < R+60m. The reserve is inside the operation budget, not added to it. The theorem starts at **commit of revocation**, as the accepted source contract specifies; it is not a measured request-to-commit SLA for administration.

| Required invariant | Evidence / exact limit |
|---|---|
| Retry, refresh and new request cannot extend the admitted durable operation | Versioned/unversioned uniqueness, immutable persisted cutoff, changed command key and post-expiry retry tests. A duplicate never receives another executor; a newly captured request deadline cannot renew the ledger row |
| No successful confirmation after 30m | Original deadline at stages/COMMIT/result; HTTP serialization and OnStarting gate; late committed review test observes persisted review and denied success. Session adapters recheck qualification/lifetime after ACK and before headers |
| No unbounded work after cancellation | Executors are awaited, no Task.Run/WaitAsync detachment, token spans DB/file I/O. **Physical termination NOT PROVEN** for kernel I/O, decoder/hash CPU, COMMIT, disposal or transport |
| Unknown COMMIT cannot automatically replay | Real ACK-loss reservation tests; injected unknown domain and upload/delete metadata COMMIT tests; fresh context/request finds original attempt and cannot execute. No retrying execution strategy in new writer |
| Stop within 60m of committed revoke | Conditional 15+30=45 proof and revoke-during-operation test. Fresh refresh/switch excludes revoked grant. **Deployment envelope NOT QUALIFIED**; no unconditional wall-clock claim |

Concrete unresolved physical obligations:

| Operation | Why software cancellation is insufficient | Minimum necessary mechanism / qualification |
|---|---|---|
| Work/review/message and file metadata COMMIT | PostgreSQL/WAL/fsync/ACK can remain in flight after cancellation; ACK loss is not rollback | Qualified DB/OS/storage/network bound including rollback/disposal and COMMIT within reserve; appropriate server timeouts and observed cancellation/termination. A timeout alone cannot prove no later commit |
| Upload body/read/validation/Store/Flush/Dispose/rename | Streams may ignore cancellation; validation is synchronous; filesystem kernel waits and rename are not cancellable | Bounded input and concurrency plus qualified FS/CPU/scheduler envelope; if workload must be terminated, a supervised worker and proof of process/I/O termination. Killing a process alone does not prove uninterruptible kernel I/O has ended |
| Delete/unlink and retained staging cleanup | Synchronous File.Delete can block; cleanup is not independently scheduled/bounded | Separate trusted, bounded reconciliation/cleanup with finite capacity and verified writer/DB outcome. Do not delete uncertain originals solely because a query returns no row or a deadline passed |
| Private file read and HTTP result/cookie delivery | Read/dispose/write cancellation is cooperative; bytes already queued cannot be recalled; proxy buffering can delay delivery | Qualified end-to-end egress/queue bound and absolute response-age enforcement through the controlled edge; no late-forwarding claim for an unqualified proxy |
| Login/refresh/signing | CPU scheduling, password hashing, DB locks/commit and response sending are not hard-real-time | Qualified clocks plus bounded scheduling/CPU/DB/egress; existing password/input limits do not constitute deployment proof |
| All enabled requests | No configured finite teacher admission queue or measured saturation envelope in this adapter | Explicit host concurrency/pending capacity, overload rejection, storage quotas, clock-loss/fault monitoring and bounded cleanup. There is no new queue infrastructure in this change |

Local `timedatectl show -p NTPSynchronized -p NTP` reported both values `yes`; this does not certify UTC/rate/error bounds. The supplied `UnprovenLocalClockVerifier` still refuses qualification. The existing local clock verifier has not been qualified for production by this task. No clock override, new grant freshness cache, fs-verity requirement or STORAGE-PROFILE-02 was introduced.
