# Content Architecture

## Цель

LMS не должна превращаться в CMS для создания учебных материалов.
Учебные материалы создаются как обычные Markdown-файлы, а LMS отвечает за их отображение и учебный процесс вокруг них.

## Контентный контур

```text
Git repository
      ↓
Course Import
      ↓
Course Validator
      ↓
Course Compiler
      ↓
Immutable Published Version
      ↓
LMS Renderer
```

## Единый renderer

Один Markdown renderer SHOULD использоваться для:

- `course.md`;
- `lesson.md`;
- `problem.md`;
- сообщений ученика;
- сообщений преподавателя.

Renderer отвечает за:

- Markdown;
- LaTeX;
- локальные изображения;
- локальные файлы;
- безопасные HTTPS-ссылки;
- распознавание поддерживаемых видеохостингов;
- `attachment://` в пользовательских сообщениях;
- санитизацию результирующего HTML.

## Видео

В исходном Markdown хранится обычный URL.

```markdown
https://rutube.ru/video/...
```

Frontend распознаёт провайдера и MAY показать embedded player.

Неизвестный provider отображается обычной ссылкой.

## Версионность

Опубликованная версия MUST быть immutable.

Изменение Git-репозитория создаёт новую версию и не должно изменять уже выданные задания ретроактивно.

## Почему это важно

Такой подход:

- исключает разработку сложного редактора;
- позволяет редактировать материалы через Codex;
- даёт Git history/diff/rollback;
- делает курс переносимым;
- отделяет педагогический контент от приложения;
- уменьшает связанность frontend/backend с форматом материалов.
