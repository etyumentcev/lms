# Синтетический набор пилота

Идемпотентно наполняет уже запущенный локальный Compose двумя организациями,
тремя независимыми курсами, тремя группами и 54 зачислениями. Полные планы занятий
24/24/18 компилируются и публикуются, после чего каждой группе назначаются первые
пять задач курса. Скрипт использует только штатные HTTPS API и не пишет данные
напрямую в БД.

Набор использует только синтетические ФИО и штатные HTTPS bootstrap/admin/editor
API. Посещаемость дистанционной группы не создаётся и не выводится из активности
LMS. Создаётся только первая 36-часовая дистанционная программа: `ProgramSeries`,
общая статистика и автоматический перенос в следующие программы отсутствуют.

## Запуск

Из корня репозитория, когда `docker compose up` уже запущен:

```sh
./tools/pilot_seed/run.sh
```

`run.sh` запускает trusted host proxy как transient user-systemd service. API
передаёт ему ZIP по Unix socket, а proxy вызывает принятый B07b-C1 sandbox с
cgroup/bubblewrap. Нужны Linux x86_64, работающий `systemd --user`, Python 3.14.4,
bubblewrap 0.11.1, Node 24.19.0 и KaTeX 0.16.47. Worker не видит сеть, БД или
секреты; неподдерживаемое окружение завершается fail-closed. Socket adapter
разрешён только при `ASPNETCORE_ENVIRONMENT=Development`; production/default
runner не изменён.

Локальный Compose поднимает лимиты активации до 400. Первое наполнение с тремя
компиляциями обычно занимает меньше минуты. Повторный запуск проверяет и
дозаполняет набор без удаления данных, повторной публикации и перезаписи истории.

Локальные идентификаторы и пароль сохраняются с правами `0600` в:

- `tools/pilot_seed/.local/credentials.json` — организации и логины;
- `tools/pilot_seed/.local/password` — общий пароль синтетических аккаунтов;
- `tools/pilot_seed/.local/state.json` — checkpoint идемпотентного сценария.

Каталог `.local` исключён из Git. Не коммитьте эти файлы и не используйте пароль
для реальных учётных записей.

PostgreSQL и служебные данные находятся в именованных Docker volumes и переживают
`docker compose down` с последующим `docker compose up`.
Команда `docker compose down -v` намеренно удаляет эти volumes; после неё снова
запустите seed-сценарий. Если удалены volumes, но сохранён `.local`, сценарий
обнаружит отсутствие прежних организаций и создаст набор заново.
